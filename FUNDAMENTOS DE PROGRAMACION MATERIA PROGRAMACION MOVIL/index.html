Fundamentos de Programación: El Inicio del Viaje 🧠

Todo gran viaje comienza con un primer paso. En el universo del software, ese paso es comprender los conceptos fundamentales que sustentan todo lo que construirás. No se trata solo de aprender un lenguaje, sino de aprender a **pensar de forma lógica, estructurada y creativa** para resolver problemas.

¿Qué es la Programación? 🤔

1️⃣ Es el proceso de diseñar, escribir, probar y mantener el código fuente de programas informáticos. Es el lenguaje universal que usamos los humanos para darle instrucciones precisas a una computadora.

2️⃣ Es el arte de traducir soluciones a problemas del mundo real a una secuencia de pasos lógicos que una máquina pueda entender y ejecutar. Es el puente entre una idea y su implementación funcional.

Algoritmo 📝

1️⃣ Es una secuencia de pasos finitos, lógicos y no ambiguos que describen la solución a un problema específico. Es la "receta" detallada que un programador diseña antes de escribir una sola línea de código.

2️⃣ Es el plano de la solución. Un buen algoritmo es eficiente, correcto y legible. La calidad de tu software depende directamente de la calidad de tus algoritmos.

El Desarrollador de Software: Roles, Niveles y Oportunidades 🚀

Un desarrollador de software es un profesional que aplica principios de ingeniería y ciencias de la computación para diseñar, desarrollar, probar y mantener software. No es un rol único, sino una carrera con una progresión clara y roles especializados.

  • Junior Developer (Jr.): (0-2 años de experiencia) Se enfoca en aprender el stack tecnológico, escribir código bien definido bajo supervisión y corregir bugs. Su principal objetivo es la ejecución y el aprendizaje.
  • Mid-level Developer (Semi-Senior / Ssr.): (2-5 años) Trabaja de forma autónoma en funcionalidades completas, participa en decisiones de diseño y ayuda a los desarrolladores junior. Domina las herramientas y entiende el negocio.
  • Senior Developer (Sr.): (5+ años) No solo escribe código excelente, sino que diseña sistemas complejos. Es mentor de otros, lidera proyectos, define buenas prácticas y tiene una visión a largo plazo de la arquitectura del software. Su impacto va más allá del código.
  • Roles Especializados: A partir del nivel Senior, la carrera puede ramificarse a Tech Lead (liderazgo técnico de un equipo), Arquitecto de Software (diseño de sistemas a gran escala) o Manager de Ingeniería (gestión de personas).

Ejemplo Avanzado: Contador de Clics con Lógica de Estado

Introducimos el concepto de **estado**. Una variable (`_contador`) "recuerda" su valor entre diferentes clics, permitiendo una lógica más compleja.

📄 MainPage.xaml
<?xml version="1.0" encoding="utf-8" ?>
<ContentPage xmlns="http://schemas.microsoft.com/dotnet/2021/maui"
             xmlns:x="http://schemas.microsoft.com/winfx/2009/xaml"
             x:Class="EjemplosApp.MainPage">

    <Grid RowDefinitions="*,Auto" Padding="20">
    
        <Label x:Name="CounterLabel"
               Text="Clics: 0"
               FontSize="48"
               FontAttributes="Bold"
               HorizontalOptions="Center"
               VerticalOptions="Center"
               Grid.Row="0"/>

        <HorizontalStackLayout Spacing="10" HorizontalOptions="Center" Grid.Row="1">
            <Button Text="Incrementar (+)" Clicked="OnIncrementarClicked"/>
            <Button Text="Resetear" Clicked="OnResetearClicked" BackgroundColor="DarkSlateGray"/>
        </HorizontalStackLayout>

    </Grid>
</ContentPage>
⚡ MainPage.xaml.cs
namespace EjemplosApp;

public partial class MainPage : ContentPage
{
    // 💾 Variable de instancia (campo) para mantener el estado del contador.
    // El guion bajo (_) es una convención para campos privados.
	private int _contador = 0;

	public MainPage()
	{
		InitializeComponent();
	}

	private void OnIncrementarClicked(object sender, EventArgs e)
	{
		_contador++; // Incrementa el valor en 1
		ActualizarUI();
	}

	private void OnResetearClicked(object sender, EventArgs e)
	{
		_contador = 0; // Reinicia el valor a 0
		ActualizarUI();
	}

    // ✨ Buena práctica: un método que actualiza la UI
    private void ActualizarUI()
    {
        CounterLabel.Text = $"Clics: {_contador}";
    }
}

🧩 Reto Práctico: Mini Calculadora

Planteamiento: Crea una calculadora que tome dos números de dos campos `Entry` y, usando cuatro `Button` (Suma, Resta, Multiplica, Divide), muestre el resultado en un `Label`.

💡 Pista: Necesitarás convertir el `Text` de los `Entry` a un tipo numérico como `double` usando `double.Parse()` o `Convert.ToDouble()`. ¡Cuidado con la división por cero!

📄 MainPage.xaml (Solución)
<?xml version="1.0" encoding="utf-8" ?>
<ContentPage xmlns="http://schemas.microsoft.com/dotnet/2021/maui"
                xmlns:x="http://schemas.microsoft.com/winfx/2009/xaml"
                x:Class="RetoApp.MainPage">

    <VerticalStackLayout Spacing="10" Padding="25" VerticalOptions="Center">
        <Label Text="Mini Calculadora" FontSize="24" FontAttributes="Bold" HorizontalOptions="Center"/>
        
        <Entry x:Name="Num1Entry" Placeholder="Primer número" Keyboard="Numeric"/>
        <Entry x:Name="Num2Entry" Placeholder="Segundo número" Keyboard="Numeric"/>

        <Grid ColumnDefinitions="*,*,*,*" ColumnSpacing="10" Margin="0,15,0,0">
            <Button Grid.Column="0" Text="+" Clicked="OnOperacionClicked" CommandParameter="+" />
            <Button Grid.Column="1" Text="-" Clicked="OnOperacionClicked" CommandParameter="-" />
            <Button Grid.Column="2" Text="*" Clicked="OnOperacionClicked" CommandParameter="*" />
            <Button Grid.Column="3" Text="/" Clicked="OnOperacionClicked" CommandParameter="/" />
        </Grid>

        <Label x:Name="ResultadoLabel" Text="Resultado: " FontSize="22" HorizontalOptions="Center" Margin="0,20,0,0" />
    </VerticalStackLayout>
</ContentPage>
⚡ MainPage.xaml.cs (Solución)
namespace RetoApp;

public partial class MainPage : ContentPage
{
    public MainPage()
    {
        InitializeComponent();
    }

    private void OnOperacionClicked(object sender, EventArgs e)
    {
        try
        {
            double num1 = double.Parse(Num1Entry.Text);
            double num2 = double.Parse(Num2Entry.Text);
            double resultado = 0;

            // Obtenemos el símbolo del botón presionado
            string operacion = (sender as Button).CommandParameter.ToString();

            switch (operacion)
            {
                case "+": resultado = num1 + num2; break;
                case "-": resultado = num1 - num2; break;
                case "*": resultado = num1 * num2; break;
                case "/":
                    if (num2 == 0)
                    {
                        DisplayAlert("Error", "No se puede dividir por cero.", "OK");
                        return;
                    }
                    resultado = num1 / num2;
                    break;
            }
            ResultadoLabel.Text = $"Resultado: {resultado:F2}";
        }
        catch (Exception)
        {
            DisplayAlert("Error", "Por favor, ingresa números válidos.", "OK");
        }
    }
}

Diagramas y Flujos 📊

Diagrama de Flujo 🗺️

1️⃣ Es la representación gráfica de un algoritmo. Utiliza símbolos estandarizados para mostrar la secuencia de pasos, las decisiones y el flujo de control de un proceso, desde el inicio hasta el fin.

2️⃣ Es una herramienta visual fundamental para planificar y documentar la lógica de un programa. Ayuda a los desarrolladores a pensar en la solución de un problema antes de escribir una sola línea de código.

Simbología Clave de Diagramas de Flujo 🧩
  • Óvalo / Elipse: Representa el Inicio o Fin del proceso.
  • Rectángulo: Representa una operación o proceso (ej. resultado = a + b).
  • Rombo: Indica una decisión con dos o más salidas (Sí/No, Verdadero/Falso). Es el corazón de un `if`.
  • Paralelogramo: Simboliza la Entrada o Salida de datos (ej. leer un nombre, mostrar un resultado).
  • Flecha: Muestra la dirección del flujo, conectando los símbolos.

🎯 Nota Importante: Los diagramas son conceptuales. El código siguiente *implementa* la lógica que estos diagramas representarían. La interfaz de usuario (XAML) nos permite interactuar con esa lógica.

Ejemplo Avanzado: Flujo con Bucle (Repetición)

Diagrama mental: Inicio → Pedir un número N (Entrada) → Iniciar contador en 1 (Proceso) → ¿Contador <= N? (Decisión) → [Sí] Mostrar contador (Salida) → Incrementar contador (Proceso) → Volver a la decisión → [No] Fin.

📄 MainPage.xaml
<?xml version="1.0" encoding="utf-8" ?>
<ContentPage xmlns="http://schemas.microsoft.com/dotnet/2021/maui"
             xmlns:x="http://schemas.microsoft.com/winfx/2009/xaml"
             x:Class="DiagramasApp.MainPage">
    <VerticalStackLayout Spacing="10" Padding="20">
        <Label Text="Contador Numérico" FontSize="22" FontAttributes="Bold"/>
        <Entry x:Name="LimiteEntrada" Placeholder="Contar hasta el número..." Keyboard="Numeric"/>
        <Button Text="Iniciar Conteo" Clicked="OnContarClicked"/>
        <ScrollView Margin="0,15,0,0">
            <Label x:Name="ConteoSalida" FontSize="18"/>
        </ScrollView>
    </VerticalStackLayout>
</ContentPage>
⚡ MainPage.xaml.cs
using System.Text; // Para construir el string eficientemente

namespace DiagramasApp;

public partial class MainPage : ContentPage
{
    public MainPage() { InitializeComponent(); }

    private void OnContarClicked(object sender, EventArgs e)
    {
        if (!int.TryParse(LimiteEntrada.Text, out int limite)) return;

        var stringBuilder = new StringBuilder();

        // 🧠 Bucle (estructura de repetición del diagrama)
        for (int i = 1; i <= limite; i++)
        {
            // Proceso y Salida dentro del bucle
            stringBuilder.AppendLine($"Número: {i}");
        }

        ConteoSalida.Text = stringBuilder.ToString();
    }
}

🧩 Reto Práctico: Validador de Contraseñas

Planteamiento: Dibuja (mentalmente o en papel) el diagrama de flujo para un validador de contraseñas. La lógica es: Inicio → Pedir contraseña → ¿Tiene más de 8 caracteres? → [No] Mostrar error y Fin. → [Sí] ¿Contiene un número? → [No] Mostrar error y Fin. → [Sí] Mostrar "Contraseña segura" y Fin. Luego, implementa esa lógica en una app .NET MAUI.

💡 Pista: Necesitarás anidar estructuras `if`. Para comprobar si una cadena contiene un número, puedes usar LINQ con `contrasena.Any(char.IsDigit)`.

📄 MainPage.xaml (Solución)
<?xml version="1.0" encoding="utf-8" ?>
<ContentPage xmlns="http://schemas.microsoft.com/dotnet/2021/maui"
             xmlns:x="http://schemas.microsoft.com/winfx/2009/xaml"
             x:Class="RetoDiagramas.MainPage">
    <VerticalStackLayout Spacing="15" Padding="30" VerticalOptions="Center">
        <Label Text="Validador de Contraseña" FontSize="22" FontAttributes="Bold"/>
        <Entry x:Name="PassEntry" Placeholder="Ingrese una contraseña" IsPassword="True"/>
        <Button Text="Validar" Clicked="OnValidarClicked"/>
        <Label x:Name="ResultadoValidacion" FontSize="18" FontAttributes="Bold" HorizontalOptions="Center"/>
    </VerticalStackLayout>
</ContentPage>
⚡ MainPage.xaml.cs (Solución)
using System.Linq; // Necesario para .Any()

namespace RetoDiagramas;

public partial class MainPage : ContentPage
{
    public MainPage() { InitializeComponent(); }

    private void OnValidarClicked(object sender, EventArgs e)
    {
        string password = PassEntry.Text;

        // Primera Decisión: Longitud
        if (password.Length <= 8)
        {
            MostrarResultado("🔴 Error: Debe tener más de 8 caracteres.", Colors.Red);
            return; // Termina el flujo
        }

        // Segunda Decisión: Contiene un número
        if (!password.Any(char.IsDigit))
        {
            MostrarResultado("🟠 Error: Debe contener al menos un número.", Colors.Orange);
            return; // Termina el flujo
        }

        // Si pasa todas las validaciones
        MostrarResultado("✅ ¡Contraseña segura!", Colors.Green);
    }

    private void MostrarResultado(string mensaje, Color color)
    {
        ResultadoValidacion.Text = mensaje;
        ResultadoValidacion.TextColor = color;
    }
}

¿Qué es C# (C Sharp)? El Lenguaje de la Productividad 💻

Creado a principios de los 2000 por el legendario Anders Hejlsberg, C# nació con un objetivo claro: combinar la potencia y el control de C++ con la rapidez de desarrollo de Visual Basic. El resultado es un lenguaje de programación moderno, elegante y multiparadigma (orientado a objetos, funcional, etc.).

Es un lenguaje fuertemente tipado y compilado, lo que significa que muchos errores se detectan antes de que la aplicación se ejecute, resultando en software más robusto y seguro. Es el lenguaje principal y ciudadano de primera clase del universo .NET.

El Arsenal de C#: Características que te Dan Superpoderes

LINQ (Language Integrated Query)

Permite escribir consultas a colecciones de datos (listas, bases de datos, XML) directamente en C# con una sintaxis similar a SQL. Transforma código complejo de bucles y condicionales en una sola línea expresiva. Es, para muchos, la característica más amada del lenguaje.

Async / Await

Simplifica radicalmente la programación asíncrona. Permite escribir código que realiza operaciones largas (como llamadas a una API o acceso a archivos) sin bloquear la interfaz de usuario, manteniendo el código tan legible como si fuera síncrono. Es esencial para crear apps fluidas y responsivas.

Seguridad de Tipos y Nulos

Al ser fuertemente tipado, C# evita una clase entera de errores en tiempo de ejecución. Con las características más recientes de "tipos de referencia anulables", el compilador te ayuda a evitar la infame NullReferenceException, uno de los bugs más comunes en la historia de la programación.

¿Backend y Frontend? ↔️ La Gran Separación

En .NET, esta separación es un principio de diseño fundamental que permite la especialización y la colaboración.

  • 🎨 **Frontend:** Es la interfaz de usuario (UI), todo lo que el usuario ve y toca. En nuestro mundo, se construye con XAML, un lenguaje declarativo que describe la estructura y apariencia de los controles. Es el dominio de la experiencia de usuario (UX) y el diseño.
  • 🧠 **Backend:** Es el cerebro de la aplicación. Se escribe en C# y contiene la lógica de negocio, el acceso a datos, las llamadas a APIs y todos los procesos que ocurren "tras bambalinas". Es el dominio de la lógica y la arquitectura.

El XAML solo define un contenedor (`VerticalStackLayout`). El C# (Backend) crea y añade dinámicamente nuevos controles (`Button`) a ese contenedor, basándose en una lógica interna.

    <VerticalStackLayout Padding="20" Spacing="10">
        <Label Text="Generador de UI Dinámica" FontSize="20" FontAttributes="Bold"/>
        <Button Text="Añadir Nuevo Botón" Clicked="OnAnadirBotonClicked"/>>
        
        <ScrollView Margin="0,15,0,0">
            <!-- Este Layout es un contenedor vacío, C# lo llenará -->
            <VerticalStackLayout x:Name="ContenedorDinamico" Spacing="5"/>
        </ScrollView>
    </VerticalStackLayout>
</ContentPage>
⚡ MainPage.xaml.cs (Backend)
namespace EcosistemaApp;

public partial class MainPage : ContentPage
{
    private int _contadorBotones = 0;

    public MainPage() { InitializeComponent(); }

    private void OnAnadirBotonClicked(object sender, EventArgs e)
    {
        _contadorBotones++;

        // 🧠 C# crea un nuevo objeto de UI que no existía en XAML
        var nuevoBoton = new Button
        {
            Text = $"Botón Dinámico #{_contadorBotones}",
            BackgroundColor = Colors.CornflowerBlue,
            TextColor = Colors.White
        };

        // Añadimos un evento al nuevo botón
        nuevoBoton.Clicked += OnBotonDinamicoClicked;
        
        // Añadimos el control recién creado al contenedor del Frontend
        ContenedorDinamico.Children.Add(nuevoBoton);
    }

    private void OnBotonDinamicoClicked(object sender, EventArgs e)
    {
        // Obtenemos la referencia al botón que fue presionado
        var botonPresionado = sender as Button;
        DisplayAlert("Botón Dinámico", $"Has presionado: {botonPresionado.Text}", "OK");
    }
}

🧩 Reto Práctico: Paleta de Colores

Planteamiento: Crea una interfaz con tres `Slider`s (deslizadores), uno para Rojo (R), uno para Verde (G) y uno para Azul (B). Cada `Slider` irá de 0 a 255. Debajo, coloca un `Frame` o `BoxView` que servirá como muestra de color. El reto consiste en que cada vez que un `Slider` cambie de valor, el color del `Frame` se actualice en tiempo real, combinando los tres valores RGB.

💡 Pista: Define los `Slider`s en XAML y asígnales el evento `ValueChanged`. En el C# (Backend), crea un solo método manejador para los tres eventos. Dentro, lee los valores (`.Value`) de los tres `Slider`s, crea un nuevo objeto `Color` usando `Color.FromRgb(r, g, b)`, y asígnalo a la propiedad `BackgroundColor` del `Frame`.

📄 MainPage.xaml (Solución)
<?xml version="1.0" encoding="utf-8" ?>
<ContentPage xmlns="http://schemas.microsoft.com/dotnet/2021/maui"
             xmlns:x="http://schemas.microsoft.com/winfx/2009/xaml"
             x:Class="RetoEcosistema.MainPage">
    <VerticalStackLayout Spacing="15" Padding="30">
        <Label Text="Paleta de Colores RGB" FontSize="22" FontAttributes="Bold"/>
        
        <!-- Muestra de Color -->
        <Frame x:Name="ColorDisplayFrame" HeightRequest="100" BackgroundColor="Black" BorderColor="Gray"/>
        
        <!-- Slider Rojo -->
        <Label x:Name="RedLabel" Text="Rojo: 0"/>
        <Slider x:Name="RedSlider" Minimum="0" Maximum="255" ValueChanged="OnColorSliderChanged"/>
        
        <!-- Slider Verde -->
        <Label x:Name="GreenLabel" Text="Verde: 0"/>
        <Slider x:Name="GreenSlider" Minimum="0" Maximum="255" ValueChanged="OnColorSliderChanged"/>
        
        <!-- Slider Azul -->
        <Label x:Name="BlueLabel" Text="Azul: 0"/>
        <Slider x:Name="BlueSlider" Minimum="0" Maximum="255" ValueChanged="OnColorSliderChanged"/>
    </VerticalStackLayout>
</ContentPage>
⚡ MainPage.xaml.cs (Solución)
namespace RetoEcosistema;

public partial class MainPage : ContentPage
{
    public MainPage() { InitializeComponent(); }

    private void OnColorSliderChanged(object sender, ValueChangedEventArgs e)
    {
        // 🧠 La lógica de C# se ejecuta cada vez que un slider cambia.
        
        // Convertimos los valores double a int para el color
        int red = (int)RedSlider.Value;
        int green = (int)GreenSlider.Value;
        int blue = (int)BlueSlider.Value;

        // Actualizamos las etiquetas para mostrar los valores numéricos
        RedLabel.Text = $"Rojo: {red}";
        GreenLabel.Text = $"Verde: {green}";
        BlueLabel.Text = $"Azul: {blue}";

        // Creamos el nuevo color y actualizamos el Frontend
        ColorDisplayFrame.BackgroundColor = Color.FromRgb(red, green, blue);
    }
}

Datos y Variables 📦

Tipos de Dato 🏷️

1️⃣ Es un atributo que especifica el tipo de información que una variable puede contener (ej. int para enteros, string para texto, bool para verdadero/falso). Define qué operaciones se pueden realizar sobre el dato.

2️⃣ Es la clasificación de los datos que le indica al compilador cómo el programador pretende utilizar la información. Es la base para un código seguro y eficiente en el uso de memoria.

Variable 📝

1️⃣ Es un espacio en la memoria del computador con un nombre simbólico (un identificador) asociado a un valor que puede cambiar durante la ejecución del programa.

2️⃣ Es una "caja" con una etiqueta donde guardamos información para usarla y modificarla más tarde. Cada caja está diseñada para un tipo específico de dato.

Constante 🗿

1️⃣ Es un tipo de variable cuyo valor no puede ser modificado después de su asignación inicial. Se declara usando la palabra clave const.

2️⃣ Se utiliza para almacenar valores fijos y significativos que se usan repetidamente en el programa, como el valor de PI o una URL de configuración. Esto mejora la legibilidad y facilita el mantenimiento del código.

            <DatePicker x:Name="FechaNacimientoPicker"/>
            <Entry x:Name="SalarioEntry" Placeholder="Salario Anual" Keyboard="Numeric"/>
            <HorizontalStackLayout Spacing="10">
                <Label Text="Miembro Activo"/>
                <Switch x:Name="ActivoSwitch"/>

⚡ MainPage.xaml.cs (Solución)
namespace RetoDatos;

public partial class MainPage : ContentPage
{
    public MainPage() { InitializeComponent(); }

    private void OnGuardarPerfilClicked(object sender, EventArgs e)
    {
        // Declaración de variables con sus tipos correspondientes
        string nombre = NombreEntry.Text;
        DateTime fechaNacimiento = FechaNacimientoPicker.Date;
        double.TryParse(SalarioEntry.Text, out double salario);
        bool esActivo = ActivoSwitch.IsToggled;

        // Cálculo de la edad
        int edad = DateTime.Today.Year - fechaNacimiento.Year;
        if (fechaNacimiento.Date > DateTime.Today.AddYears(-edad))
        {
            edad--;
        }

            $"Nombre: {nombre}\n" +
            $"Edad: {edad} años\n" +
            $"Salario: {salario:C}\n" + // C formatea como moneda

    }

Colecciones de Datos (Arrays, Listas) 🗂️

Array (Arreglo) 🧱

1️⃣ Es una colección de elementos del mismo tipo con un tamaño fijo, que se define en su creación. Los elementos se acceden a través de un índice numérico (comenzando en 0).

2️⃣ Imagina una caja de huevos: tiene un número fijo de espacios y todos los espacios son para huevos. Son muy eficientes en memoria y velocidad, pero inflexibles en tamaño.

Lista (`List`) 🔗

1️⃣ Es una colección de elementos del mismo tipo con un tamaño dinámico. Puedes añadir, eliminar y modificar elementos fácilmente después de su creación.

2️⃣ Es como una lista de compras: puedes añadir nuevos artículos o tachar los que ya tienes en cualquier momento. Es la colección más versátil y comúnmente utilizada en C#.

Matriz (Array Multidimensional) 🎲

1️⃣ Es un array con más de una dimensión. La más común es la de dos dimensiones (un array 2D), que se puede visualizar como una cuadrícula o tabla con filas y columnas.

2️⃣ Se utiliza para representar datos que tienen una estructura de rejilla, como un tablero de ajedrez, un mapa de asientos en un cine o los píxeles de una imagen.

Ejemplo Avanzado: Generador de Tablero con Matriz 2D

Utilizamos una matriz de 3x3 para representar un tablero. La lógica en C# recorre la matriz y genera dinámicamente una cuadrícula de `Button`s.

📄 MainPage.xaml
<?xml version="1.0" encoding="utf-8" ?>
<ContentPage xmlns="http://schemas.microsoft.com/dotnet/2021/maui"
             xmlns:x="http://schemas.microsoft.com/winfx/2009/xaml"
             x:Class="ColeccionesApp.MainPage">
    <VerticalStackLayout Padding="20" Spacing="15">
        <Button Text="Generar Tablero 3x3" Clicked="OnGenerarTableroClicked"/>
        <!-- Este Grid se llenará dinámicamente con botones -->
        <Grid x:Name="TableroGrid" 
              RowSpacing="5" ColumnSpacing="5" 
              VerticalOptions="CenterAndExpand" 
              HorizontalOptions="CenterAndExpand">
        </Grid>
    </VerticalStackLayout>
</ContentPage>
⚡ MainPage.xaml.cs
namespace ColeccionesApp;

public partial class MainPage : ContentPage
{
    // ⚪️ Matriz de 3 filas y 3 columnas
    private string[,] _tableroState = new string[3, 3];

    public MainPage() { InitializeComponent(); }

    private void OnGenerarTableroClicked(object sender, EventArgs e)
    {
        TableroGrid.Clear(); // Limpiar tablero anterior
        TableroGrid.RowDefinitions.Clear();
        TableroGrid.ColumnDefinitions.Clear();

        // 🧠 Creamos las filas y columnas del Grid
        for (int i = 0; i < 3; i++)
        {
            TableroGrid.RowDefinitions.Add(new RowDefinition { Height = 80 });
            TableroGrid.ColumnDefinitions.Add(new ColumnDefinition { Width = 80 });
        }

        // 🧠 Recorremos la matriz 2D con bucles anidados
        for (int fila = 0; fila < 3; fila++)
        {
            for (int col = 0; col < 3; col++)
            {
                var celda = new Button { Text = $"({fila},{col})", FontSize = 12 };
                TableroGrid.Add(celda, column: col, row: fila);
            }
        }

Operadores: El Lenguaje de la Lógica 🧮

Si las variables son los sustantivos de la programación (las "cosas"), los operadores son los **verbos**: las acciones que nos permiten manipular, comparar y combinar esas cosas. Son los símbolos que dan vida a nuestros datos, permitiéndonos realizar desde cálculos matemáticos simples hasta reglas de negocio increíblemente complejas. Dominar los operadores es dominar el flujo de la lógica.

Operadores Aritméticos ➕➖✖️➗

Qué son: Son los operadores que ya conoces de las matemáticas. Se usan para realizar operaciones numéricas.

  • + (Suma), - (Resta), * (Multiplicación), / (División).
  • % (Módulo): Devuelve el residuo de una división. Es increíblemente útil para saber si un número es par (numero % 2 == 0) o para ciclos.

Razón de Ser: Son el pilar de cualquier cálculo. Desde calcular el total de un carrito de compras (double total = subtotal + (subtotal * 0.18);) hasta procesar datos científicos, son indispensables.

Operadores de Comparación ⚖️

Qué son: Se utilizan para comparar dos valores. Su resultado es siempre un valor booleano: true o false.

  • == (Igual a), != (No igual a).
  • > (Mayor que), < (Menor que).
  • >= (Mayor o igual que), <= (Menor o igual que).

Razón de Ser: Son el cerebro de la toma de decisiones. Son la pregunta que se hace dentro de una estructura if para decidir qué camino tomar. Ejemplo: if (edad >= 18).

Operadores Lógicos 🧠

Qué son: Se usan para combinar múltiples expresiones booleanas en una sola.

  • && (AND Lógico): Devuelve true solo si ambas condiciones son verdaderas.
  • || (OR Lógico): Devuelve true si al menos una de las condiciones es verdadera.
  • ! (NOT Lógico): Invierte un valor booleano (convierte true en false y viceversa).

Razón de Ser: Permiten crear reglas de negocio complejas y realistas. Ejemplo: if (usuarioValido && tienePermisosDeAdmin).

switch: La Selección Múltiple

Definición y Contexto

La instrucción switch permite evaluar una variable o expresión y comparar su valor con una lista de posibles valores constantes, llamados case.   • Contrincante Principal: La cadena if/else if/else. Se prefiere switch cuando se evalúa una única variable contra múltiples valores discretos (números, strings, enums). Es más legible en estos escenarios.

  • Procesamiento de Colecciones: Recorrer una lista de usuarios para enviarles un email a cada uno.

  • Operaciones Matemáticas: Calcular factoriales, sumatorias o simulaciones que requieren múltiples pasos.
  • Lectura de Datos: Leer un archivo línea por línea hasta llegar al final.

Manejo de Excepciones: El Plan de Contingencia ☣️

El software perfecto no existe. Los errores son inevitables: un usuario introduce texto donde va un número, un archivo no se encuentra, una conexión a internet se cae. La diferencia entre un desarrollador aficionado y un profesional es cómo se preparan para lo inesperado. El manejo de excepciones es el plan de contingencia de tu código; es el sistema inmunológico que detecta problemas y reacciona de forma controlada en lugar de dejar que la aplicación "muera" abruptamente.

¿Qué es una Excepción? 💥

1️⃣ Una excepción es un objeto que representa una condición de error o un evento inesperado que ocurre durante la ejecución de un programa. Cuando ocurre un error, se "lanza" (`throw`) una excepción, interrumpiendo el flujo normal del programa.

2️⃣ Es la forma estructurada y orientada a objetos que tiene .NET para señalizar y manejar problemas. En lugar de devolver códigos de error confusos, el sistema crea un objeto detallado con información sobre qué salió mal, dónde y por qué.

La Sintaxis Sagrada: `try`, `catch` y `finally`
  • try { ... }: El bloque "zona de peligro". Aquí pones el código que sospechas que podría fallar (ej. una conversión de tipos, una operación de red, acceso a un archivo).
  • catch (ExceptionType ex) { ... }: El bloque "manejador de emergencias". Si una excepción del tipo especificado (`ExceptionType`) ocurre dentro del `try`, el flujo del programa salta inmediatamente a este bloque. Aquí es donde manejas el error: registrándolo, mostrando un mensaje al usuario, etc.
  • finally { ... }: El bloque "equipo de limpieza". Este bloque se ejecuta siempre, sin importar si hubo una excepción o no. Es crucial para liberar recursos importantes (como cerrar conexiones de bases de datos o archivos) para evitar fugas de memoria.
Genéricas vs. Tipificadas: El Especialista Médico 🩺

Puedes atrapar excepciones de forma genérica o específica, y el orden importa.

  • Genérica (catch (Exception ex)): Es como un médico general. Atrapa cualquier tipo de excepción porque todas heredan de la clase base `Exception`. Es útil como último recurso, pero a menudo es demasiado vago.
  • Tipificada o Específica (catch (FormatException ex)): Es como un cardiólogo. Atrapa un tipo de error muy concreto. Esto te permite dar respuestas mucho más precisas al usuario. La mejor práctica es siempre atrapar las excepciones más específicas primero, y dejar la genérica para el final.
  • Comunes en .NET: NullReferenceException, FormatException, FileNotFoundException, ArgumentNullException, InvalidOperationException.

Colecciones de Datos (Arrays, Listas) 🗂️

Array (Arreglo) 🧱

1️⃣ Es una colección de elementos del mismo tipo con un tamaño fijo, que se define en su creación. Los elementos se acceden a través de un índice numérico (comenzando en 0).

2️⃣ Imagina una caja de huevos: tiene un número fijo de espacios y todos los espacios son para huevos. Son muy eficientes en memoria y velocidad, pero inflexibles en tamaño.

Lista (`List`) 🔗

1️⃣ Es una colección de elementos del mismo tipo con un tamaño dinámico. Puedes añadir, eliminar y modificar elementos fácilmente después de su creación.

2️⃣ Es como una lista de compras: puedes añadir nuevos artículos o tachar los que ya tienes en cualquier momento. Es la colección más versátil y comúnmente utilizada en C#.

Matriz (Array Multidimensional) 🎲

1️⃣ Es un array con más de una dimensión. La más común es la de dos dimensiones (un array 2D), que se puede visualizar como una cuadrícula o tabla con filas y columnas.

2️⃣ Se utiliza para representar datos que tienen una estructura de rejilla, como un tablero de ajedrez, un mapa de asientos en un cine o los píxeles de una imagen.

Funciones (o Métodos) ⚙️

Si las variables son los ladrillos y las estructuras de control son el plano, las funciones son las herramientas especializadas y reutilizables que usamos para construir. Son el pilar de la programación modular, organizada y eficiente. Un programa robusto es, en esencia, una colección bien orquestada de funciones que colaboran para lograr un objetivo complejo.

¿Qué es una Función y por qué es Integral?

1️⃣ Una función (llamada "método" en C#) es un bloque de código autocontenido y con un nombre único que realiza una tarea específica. Este bloque puede ser "llamado" o "invocado" desde cualquier otra parte del programa, evitando así la repetición de código.

2️⃣ Son la unidad fundamental de la organización y la reutilización. Su razón de ser es encapsular una lógica en un solo lugar. Si necesitas cambiar esa lógica (por ejemplo, mejorar el cálculo de un impuesto), solo lo haces dentro de la función, y el cambio se refleja en todos los lugares donde se llama. Esto se conoce como el principio DRY (Don't Repeat Yourself - No te repitas).

Tipos de Funciones y sus Componentes
  • void (Funciones Procedimentales): Son funciones que "Hacen" algo. Realizan una acción o una secuencia de pasos, como modificar la UI, guardar un archivo o imprimir algo en consola. No devuelven ningún valor al código que las llamó. Su firma incluye la palabra clave void.
  • Funciones con Retorno (Funciones Puras): Son funciones que "Calculan" algo. Toman unas entradas, las procesan y devuelven un único resultado. El tipo de dato que devuelven (int, string, bool, etc.) se especifica en su firma. Usan la palabra clave return para entregar el valor.
  • Parámetros (Entradas): Son las variables que una función acepta para poder trabajar. Son los "ingredientes" que la función necesita para producir un resultado. Hacen que las funciones sean flexibles y genéricas.
  • Firma del Método: Es la combinación única del modificador de acceso (ej. `private`), el tipo de retorno, el nombre del método y sus parámetros (ej. `private string FormatearNombre(string nombre)`). Define cómo se identifica y se llama a la función.

        const string SIMBOLOS = "!@#$%^&*()_-+=";

Programación Orientada a Objetos (POO) 🏛️

La POO es más que una técnica de programación; es una filosofía, un **paradigma** para estructurar el software. En lugar de pensar en términos de datos y lógica por separado, la POO nos invita a modelar el mundo real (o un mundo conceptual) a través de **"objetos"**. Un objeto es una entidad que agrupa en una sola unidad tanto sus **datos (atributos o propiedades)** como los **comportamientos que pueden actuar sobre esos datos (métodos)**. C# es, desde su núcleo, un lenguaje orientado a objetos.

Clases y Objetos: El Molde y la Galleta

🔵 **Clase:** Es el molde, la plantilla o el plano a partir del cual se crean los objetos. Define las propiedades y métodos que tendrán todos los objetos de ese tipo. Por ejemplo, una clase Vehiculo.

🚗 **Objeto:** Es una instancia de una clase. Es la "galleta" creada a partir del "molde". Si Vehiculo es la clase, un objeto podría ser miCocheRojo y otro objeto podría ser tuMotoAzul. Cada objeto tiene sus propios valores para las propiedades definidas en la clase (color, marca, velocidad_actual).

Anatomía de una Clase: Atributos, Propiedades y Métodos

Para entender la POO, debemos diseccionar una clase. Sus componentes principales son los que almacenan datos y los que definen comportamientos.

Atributos (o Campos) 💾

Qué son: Son variables declaradas directamente dentro de una clase que almacenan el estado interno de un objeto. Por convención en C#, los atributos privados suelen empezar con un guion bajo (_), como private double _saldo;.

Razón de Ser: Son el "corazón" de los datos del objeto. Generalmente se declaran como private para protegerlos del acceso directo y no controlado desde fuera de la clase. Este es el primer paso del encapsulamiento: mantener los datos internos a salvo y consistentes.

Ejemplo Conceptual: En una clase Persona, los atributos podrían ser private string _nombre; y private DateTime _fechaNacimiento;. Estos datos son la esencia de esa persona y no deberían poder modificarse arbitrariamente.

Métodos ⚙️

Qué son: Son las funciones que pertenecen a una clase. Definen los comportamientos y las acciones que un objeto puede realizar. Los métodos son los que, típicamente, operan sobre los atributos privados.

Razón de Ser: Los métodos son la forma en que un objeto "hace cosas". Permiten que el objeto interactúe con el mundo exterior y modifique su propio estado de una manera controlada. Por ejemplo, en lugar de cambiar un _saldo directamente, se llama a un método Depositar(monto), que puede incluir lógica de validación (ej. que el monto sea positivo).

Ejemplo Conceptual: En la clase Persona, un método podría ser public int CalcularEdad(). Este método usaría el atributo privado _fechaNacimiento para realizar un cálculo y devolver un resultado.

Propiedades 🚪

Qué son: Son un tipo especial de miembro de la clase en C# que se encuentran a medio camino entre un atributo y un método. Proporcionan una forma flexible y segura de exponer los atributos privados. Una propiedad parece un atributo desde fuera (se accede con objeto.Nombre), pero internamente utiliza métodos especiales llamados get (para leer el valor) y set (para asignar un valor).

Razón de Ser: Son la puerta de entrada controlada a los datos de un objeto, el pilar del encapsulamiento en C#. Permiten exponer un atributo como si fuera público, pero manteniendo la capacidad de añadir lógica de validación o cálculo en el `get` o `set`. Se puede tener una propiedad de solo lectura (solo con `get`), de solo escritura (solo con `set`, aunque es raro), o de lectura/escritura.

Ejemplo Conceptual: 

public class Persona
{
    private string _nombre;

    // Propiedad pública que controla el acceso al atributo _nombre
    public string Nombre
    {
        get { return _nombre; } // Devuelve el valor del atributo

La POO se sostiene sobre cuatro pilares fundamentales que trabajan en conjunto para crear software robusto, flexible y mantenible.

1. Encapsulamiento 캡슐

Definición y Contexto

Es el principio de agrupar datos y los métodos que operan sobre esos datos dentro de una sola unidad (la clase), y ocultar la complejidad interna del objeto al mundo exterior. El objeto expone solo lo que es necesario a través de una interfaz pública, protegiendo sus datos de manipulaciones indebidas.

¿Por qué es importante? (Razón de ser)
  • Protección de Datos: Evita que el código externo pueda modificar el estado interno de un objeto de forma inesperada o inválida. Por ejemplo, no se puede asignar una velocidad negativa a un coche.
  • Abstracción: Simplifica el uso del objeto. Para acelerar un coche, solo necesitas llamar al método Acelerar(), no necesitas saber cómo funciona el motor internamente.
  • Mantenibilidad: Si la lógica interna de un método cambia, el código que lo utiliza no se ve afectado siempre que la "firma" del método (su nombre y parámetros) no cambie.
Ejemplo Práctico: Una Clase `CuentaBancaria`

2. Herencia 👨‍👩‍👧

Definición y Contexto

La herencia es un mecanismo que permite a una clase (clase derivada o hija) adquirir las propiedades y métodos de otra clase (clase base o padre). Esto promueve la reutilización de código y establece una relación jerárquica de tipo "es un...". Por ejemplo, un Coche "es un" Vehiculo.

¿Por qué es importante? (Razón de ser)
  • Reutilización de Código: Se define un comportamiento común en una clase base (ej. `Vehiculo` tiene `Velocidad` y `Marca`) y las clases hijas (`Coche`, `Moto`) lo heredan automáticamente sin tener que reescribirlo.
  • Organización: Crea jerarquías lógicas y fáciles de entender que reflejan las relaciones del mundo real.
  • Polimorfismo (ver siguiente pilar): La herencia es la base para el polimorfismo, permitiendo tratar objetos de clases hijas como si fueran objetos de la clase padre.

3. Polimorfismo 🎭

Definición y Contexto

Del griego "muchas formas", el polimorfismo es la capacidad de los objetos de diferentes clases de responder al mismo mensaje (llamada a un método) de maneras diferentes y específicas a su tipo. Se logra a través de la herencia, permitiendo que una clase hija sobrescriba (override) un método de su clase padre para proporcionar su propia implementación.

¿Por qué es importante? (Razón de ser)
  • Flexibilidad y Extensibilidad: Permite escribir código genérico que puede trabajar con objetos de la clase padre, pero que ejecutará el comportamiento específico de la clase hija en tiempo de ejecución. Puedes añadir nuevas clases hijas sin cambiar el código que las utiliza.
  • Código Limpio: Evita tener largas cadenas de `if` o `switch` para determinar el tipo de un objeto y llamar al método correcto. Simplemente llamas al método, y el objeto "sabe" cómo responder.
Ejemplo Práctico: Calculando Áreas de Figuras

Continuamos con el ejemplo anterior. Declaramos un método `CalcularArea()` en la clase base `FiguraGeometrica` como `virtual`. Las clases hijas `Circulo` y `Rectangulo` lo sobrescriben (`override`) con su propia fórmula matemática. Luego, podemos tratar una lista de figuras de forma polimórfica.

public class Circulo : FiguraGeometrica
{
    public double Radio { get; set; }
    // 'override' proporciona una implementación específica para Círculo
    public override double CalcularArea()
    {
        return Math.PI * Radio * Radio;
    }
}

public class Rectangulo : FiguraGeometrica
{
    public double Base { get; set; }
    public double Altura { get; set; }
    // 'override' proporciona una implementación específica para Rectangulo
    public override double CalcularArea()
    {
        return Base * Altura;
    }
}

        var figuras = new List
        {
            new Circulo { Nombre = "C1", Radio = 5 },
            new Rectangulo { Nombre = "R1", Base = 10, Altura = 4 },
            new Circulo { Nombre = "C2", Radio = 1.5 }
        };

4. Abstracción 👻

Definición y Contexto

La abstracción consiste en mostrar solo las características esenciales de un objeto y ocultar los detalles irrelevantes. Mientras que el encapsulamiento oculta la complejidad interna, la abstracción se centra en definir una "idea" o "contrato" de lo que un objeto debe ser capaz de hacer, sin especificar cómo lo hace. Se implementa en C# a través de clases abstractas e interfaces.

¿Por qué es importante? (Razón de ser)
  • Definición de Contratos: Una clase abstracta o una interfaz obliga a las clases que heredan de ella a implementar ciertos métodos. Esto garantiza que todos los objetos de un tipo derivado tendrán una funcionalidad mínima común.
  • Desacoplamiento: Permite que diferentes partes de una aplicación se comuniquen a través de una abstracción (la interfaz) en lugar de implementaciones concretas. Esto hace que el sistema sea mucho más flexible y fácil de cambiar.
Ejemplo Práctico: `INotificable`

Definimos una `interface` llamada `INotificable` que tiene un solo método: `EnviarNotificacion()`. Luego, creamos clases `EmailNotifier` y `SmsNotifier` que *implementan* esa interfaz. Nuestro sistema de notificaciones puede ahora trabajar con cualquier objeto que sea `INotificable`, sin importarle si es un email o un SMS.

Patrones de Arquitectura (MVVM) 🏗️

Escribir código que funcione es el primer paso. Escribir código que sea legible, mantenible, escalable y testeable es el objetivo de un desarrollador profesional. Los patrones de arquitectura son "recetas" probadas y estandarizadas que nos ayudan a estructurar nuestro código para alcanzar esos objetivos, evitando problemas comunes y facilitando el trabajo en equipo.

MVC (Model-View-Controller): El Precursor Histórico

MVC fue uno de los primeros y más influyentes patrones para separar responsabilidades en aplicaciones con interfaz de usuario.

  • Modelo (Model): Representa los datos y la lógica de negocio. Es independiente de la interfaz.
  • Vista (View): Es la interfaz de usuario (UI). Muestra los datos del modelo al usuario.
  • Controlador (Controller): Actúa como intermediario. Recibe la entrada del usuario desde la Vista, interactúa con el Modelo y actualiza la Vista.

Aunque es muy popular en aplicaciones web (como ASP.NET MVC), en el desarrollo de UI de escritorio y móvil, su evolución, MVVM, se adapta mucho mejor.

MVVM (Model-View-ViewModel): El Estándar en .NET MAUI

MVVM es un refinamiento de MVC, diseñado específicamente para aprovechar las capacidades de las plataformas de UI modernas, como el Enlace de Datos (Data Binding). El objetivo principal es lograr una separación casi total entre la apariencia (Vista) y la lógica (ViewModel).

  • M - Modelo (Model):

    Es idéntico al del MVC. Representa las clases de nuestros datos (ej. Usuario, Producto). No sabe nada sobre la Vista o el ViewModel. Es la "verdad" de los datos.

  • V - Vista (View):

    Es la interfaz de usuario, definida casi en su totalidad en XAML (ej. MainPage.xaml). Su única responsabilidad es definir CÓMO se ve la información y CÓMO se presentan los controles. En un MVVM puro, la Vista no contiene lógica de negocio en su archivo de code-behind (ej. MainPage.xaml.cs).

  • VM - Vista-Modelo (ViewModel):

    Este es el corazón del patrón. Es una clase de C# que actúa como intermediario entre el Modelo y la Vista. Expone los datos del Modelo a través de propiedades públicas y las acciones a través de Comandos. El ViewModel no tiene ninguna referencia directa a los controles de la Vista (no sabe de `Entry`, `Button`, etc.), lo que lo hace 100% testeable.

La Magia de MVVM: Enlace de Datos y Comandos
  • 🔗 Enlace de Datos (Data Binding): Es el mecanismo que sincroniza automáticamente una propiedad del ViewModel con una propiedad de un control en la Vista. Si el valor en el ViewModel cambia, la UI se actualiza sola, y viceversa. Para que esto funcione, el ViewModel debe implementar la interfaz `INotifyPropertyChanged`.
  • ⚡ Comandos (Commands): Son objetos en el ViewModel que encapsulan una acción (como la lógica que se ejecutaría en un Clicked de un botón). La Vista se enlaza a estos comandos. Esto permite que la Vista invoque lógica en el ViewModel sin que el ViewModel sepa qué control lo invocó.

Manejo de JSON (Local y Remoto) ↔️

En el mundo conectado de hoy, las aplicaciones rara vez viven aisladas. Necesitan comunicarse, intercambiar datos con servidores, guardar configuraciones y mucho más. JSON (JavaScript Object Notation) se ha convertido en el estándar de facto para este intercambio de datos por ser ligero, legible para los humanos y fácil de procesar para las máquinas.

¿Qué es JSON? 🤔

1️⃣ JSON es un formato de texto ligero para el intercambio de datos. Se basa en un subconjunto de la notación de objetos de JavaScript, pero es completamente independiente del lenguaje. Consiste en pares de `clave: valor` (como un diccionario) y listas ordenadas de valores (como un array).

2️⃣ Es el lenguaje universal que usan las APIs para hablar entre sí. Cuando tu aplicación de .NET MAUI pide datos a un servidor, lo más probable es que el servidor le responda con un bloque de texto en formato JSON.

Ejemplo de un JSON simple:
{
  "nombre": "Ana García",
  "edad": 30,
  "esEstudiante": false,
  "cursos": [ "C#", "SQL", ".NET MAUI" ]
}
Serialización y Deserialización: El Puente entre C# y JSON
  • Serialización ➡️: Es el proceso de convertir un objeto de C# (con sus propiedades y valores) a una cadena de texto en formato JSON. Esto se hace para poder enviar el objeto a través de la red o guardarlo en un archivo.
  • Deserialización ⬅️: Es el proceso inverso. Consiste en tomar una cadena de texto JSON y convertirla de nuevo en un objeto de C# con el que tu código puede trabajar.

En el ecosistema .NET moderno, la librería principal para estas tareas es System.Text.Json, que viene integrada en .NET y es altamente optimizada.

	public MainPage() { InitializeComponent(); }

using System.Text.Json;

namespace RetoJson;

public class ConfiguracionUsuario
{
    public bool EsTemaOscuro { get; set; }
    public string TamanoFuente { get; set; }
}

public partial class MainPage : ContentPage
{
    private readonly string _configFile = Path.Combine(FileSystem.AppDataDirectory, "config.json");

    public MainPage()
    {
        InitializeComponent();
        CargarConfiguracion();
    }

    private void OnConfiguracionChanged(object sender, EventArgs e)
    {
        // Cada vez que algo cambia, guardamos toda la configuración
        GuardarConfiguracion();
        // Y aplicamos los cambios visuales
        AplicarConfiguracion();
    }

    private void GuardarConfiguracion()
    {
        var config = new ConfiguracionUsuario
        {
            EsTemaOscuro = TemaSwitch.IsToggled,
            TamanoFuente = FuentePicker.SelectedItem as string
        };
        string json = JsonSerializer.Serialize(config);
        File.WriteAllText(_configFile, json);
    }
    
    private void CargarConfiguracion()
    {
        if (File.Exists(_configFile))
        {
            string json = File.ReadAllText(_configFile);
            var config = JsonSerializer.Deserialize(json);

            // Asignamos los valores cargados a los controles
            TemaSwitch.IsToggled = config.EsTemaOscuro;
            FuentePicker.SelectedItem = config.TamanoFuente;
        }
        else
        {
            // Valores por defecto si no hay archivo
            FuentePicker.SelectedIndex = 1; // Mediano
        }
        
        AplicarConfiguracion();
    }

    private void AplicarConfiguracion()
    {
        // Aplicamos el tema a la página
        Application.Current.UserAppTheme = TemaSwitch.IsToggled ? AppTheme.Dark : AppTheme.Light;
        
        // Aplicamos el tamaño de fuente al texto de ejemplo
        switch (FuentePicker.SelectedItem as string)
        {
            case "Pequeño": TextoEjemplo.FontSize = 12; break;
            case "Mediano": TextoEjemplo.FontSize = 16; break;
            case "Grande": TextoEjemplo.FontSize = 20; break;
        }
    }
}

    private const string Url = "https://raw.githubusercontent.com/JUANCITOPENA/ARCHIVO_JSON_FOTOS_AUTOS_CLASE/refs/heads/main/vehiculos.json";
    
    // Esta es nuestra lista "maestra". Almacenará TODOS los vehículos descargados una sola vez.
    // La usaremos como la fuente de verdad para la búsqueda, evitando descargar los datos cada vez que se busca.
    private List<Vehiculo> _listaCompletaVehiculos;

	public MainPage()
    {
        // Este método es obligatorio. Inicializa todos los controles definidos en el XAML
        // para que podamos acceder a ellos en C# (ej. VehiculosCollection, CargandoIndicator).
        InitializeComponent();
        
        // Iniciamos la carga de datos de forma asíncrona.
        // El '_ =' es una forma de "descartar" la tarea, diciendo al compilador que sabemos
        // que no estamos esperando (awaiting) aquí, porque queremos que la UI se muestre inmediatamente
        // mientras los datos se cargan en segundo plano.
        _ = CargarVehiculosAsync();
    }
    
    // 'async Task' define un método asíncrono. Esto permite usar 'await' dentro de él,
    // lo que evita que la interfaz de usuario se congele mientras esperamos una operación larga (como una descarga).
    private async Task CargarVehiculosAsync()
    {
        // 'try/catch/finally' es crucial para manejar operaciones de red, que pueden fallar por muchas razones.
        try
        {
            // 'using' asegura que el objeto HttpClient (que maneja la conexión) se deseche correctamente
            // una vez que terminemos con él, liberando recursos del sistema.
            using (var httpClient = new HttpClient())
            {
                // 'await' es la palabra clave mágica. Pausa la ejecución de ESTE MÉTODO (no de la app)
                // hasta que la descarga de la URL se complete, pero permite que la UI siga siendo responsiva.
                var response = await httpClient.GetAsync(Url);

                if (response.IsSuccessStatusCode)
                {
                    // Si la descarga fue exitosa, leemos el contenido como un string.
                    string jsonContent = await response.Content.ReadAsStringAsync();
                    
                    // Deserializamos el string JSON en nuestra lista de objetos 'Vehiculo'.
                    _listaCompletaVehiculos = JsonConvert.DeserializeObject<List<Vehiculo>>(jsonContent);
                    
                    // Asignamos la lista recién creada al ItemsSource del CollectionView para que se muestre en pantalla.
                    VehiculosCollection.ItemsSource = _listaCompletaVehiculos;
                }
                else
                {
                    await DisplayAlert("Error de Red", "No se pudo obtener una respuesta del servidor.", "OK");
                }
            }
        }
        catch (Exception ex)
        {
            // Si algo sale mal (no hay internet, el JSON está mal formado, etc.), mostramos un error.
            await DisplayAlert("Error", $"No se pudieron cargar los datos: {ex.Message}", "OK");
        }
        finally
        {
            // El bloque 'finally' se ejecuta SIEMPRE, tanto si hubo éxito como si hubo un error.
            // Es el lugar perfecto para ocultar el indicador de carga.
            CargandoIndicator.IsRunning = false;
            CargandoIndicator.IsVisible = false;
        }
    }

    // Este método se ejecuta cada vez que el usuario escribe o borra un carácter en la SearchBar.
    private void OnBusquedaTextChanged(object sender, TextChangedEventArgs e)
    {
        if (_listaCompletaVehiculos == null) return; // Medida de seguridad por si el usuario escribe antes de que los datos carguen.
        
        // Obtenemos el nuevo texto de la barra de búsqueda y lo convertimos a minúsculas para una búsqueda sin distinción de mayúsculas/minúsculas.
        // 'e.NewTextValue' contiene el texto actual. Usamos '?? string.Empty' para evitar errores si es nulo.
        string textoBusqueda = e.NewTextValue?.ToLowerInvariant() ?? string.Empty;

        if (string.IsNullOrWhiteSpace(textoBusqueda))
        {
            // Si no hay texto, restauramos la vista para mostrar TODOS los vehículos de nuestra lista maestra.
            VehiculosCollection.ItemsSource = _listaCompletaVehiculos;
        }
        else
        {
            // Usamos LINQ (.Where) para filtrar la lista maestra en memoria. Es extremadamente rápido y eficiente.
            // Creamos una nueva lista 'vehiculosFiltrados' que contiene solo los vehículos que cumplen la condición.
            var vehiculosFiltrados = _listaCompletaVehiculos.Where(vehiculo => 
                (vehiculo.Marca?.ToLowerInvariant() ?? "").Contains(textoBusqueda) || 
                (vehiculo.Modelo?.ToLowerInvariant() ?? "").Contains(textoBusqueda) || 
                (vehiculo.Categoria?.ToLowerInvariant() ?? "").Contains(textoBusqueda)
            ).ToList();
            
            // Asignamos la nueva lista filtrada al CollectionView.
            VehiculosCollection.ItemsSource = vehiculosFiltrados;
        }
    }
}

CRUD y Manejo de Archivos 💾

Más allá de consumir datos de internet, una de las funcionalidades más importantes de cualquier aplicación es la capacidad de **guardar información de forma permanente en el dispositivo**. A esto se le llama **persistencia de datos**. El método más fundamental para lograrlo es a través del manejo de archivos. Las operaciones básicas que realizamos sobre estos datos persistentes se conocen por el acrónimo CRUD.

¿Qué es CRUD? El Ciclo de Vida de los Datos

CRUD es un acrónimo que describe las cuatro operaciones esenciales que se pueden realizar sobre los datos en cualquier sistema de almacenamiento (ya sea un archivo, una base de datos o una API).

  • Create (Crear): Es la operación de añadir o insertar nuevos datos. Por ejemplo, guardar una nueva nota, crear un nuevo usuario o registrar un nuevo contacto.
  • Read (Leer): Es la operación de recuperar o consultar los datos que ya han sido almacenados. Por ejemplo, abrir una nota guardada, ver la lista de contactos o cargar la configuración del usuario.
  • Update (Actualizar): Es la operación de modificar datos existentes. Por ejemplo, editar el texto de una nota, cambiar el número de teléfono de un contacto o actualizar una foto de perfil.
  • Delete (Borrar): Es la operación de eliminar datos existentes. Por ejemplo, borrar una nota, eliminar un contacto o remover un producto del carrito.

Dominar el ciclo CRUD es dominar la gestión de datos, una habilidad fundamental para cualquier desarrollador.

Manejo de Archivos en .NET MAUI

NET MAUI proporciona una forma sencilla y multiplataforma de interactuar con el sistema de archivos del dispositivo a través de la clase estática FileSystem. Esta clase nos da acceso a directorios seguros donde nuestra aplicación puede leer y escribir archivos sin preocuparse por los detalles específicos de cada sistema operativo (iOS, Android, Windows).

  • FileSystem.AppDataDirectory: Es la ruta al directorio privado de la aplicación, ideal para guardar archivos que el usuario no necesita ver directamente, como bases de datos, archivos de configuración (JSON) o notas, como veremos en el ejemplo.

    private void CargarNota()
    {
        // File.Exists comprueba si el archivo ya fue creado.
        if (File.Exists(_rutaArchivo))
        {
            try
            {
                // File.ReadAllTextAsync lee todo el contenido del archivo como un string.
                NotaEditor.Text = File.ReadAllText(_rutaArchivo);
            }
            catch (Exception ex)
            {
                DisplayAlert("Error", $"No se pudo leer la nota: {ex.Message}", "OK");

        }

            bool confirmacion = await DisplayAlert("Confirmar", "¿Estás seguro de que quieres borrar la nota? Esta acción no se puede deshacer.", "Sí, Borrar", "Cancelar");

            if (confirmacion)
            {
                try
                {
                    // File.Delete elimina el archivo del dispositivo.
                    File.Delete(_rutaArchivo);
                    NotaEditor.Text = string.Empty; // Limpiamos el editor.
                    await DisplayAlert("Éxito", "La nota ha sido borrada.", "OK");
                }
                catch (Exception ex)
                {
                    await DisplayAlert("Error", $"No se pudo borrar la nota: {ex.Message}", "OK");
                }
            }
        }
    }

    {

        if (!string.IsNullOrWhiteSpace(nombre) && !string.IsNullOrWhiteSpace(telefono))

            DisplayAlert("Éxito", "Contacto guardado.", "OK");

        }
        else
        {
            DisplayAlert("Error", "El nombre y el teléfono son requeridos.", "OK");

        {

            if (File.Exists(ruta))
            {
                TelefonoContactoEntry.Text = File.ReadAllText(ruta);

            else
            {
                DisplayAlert("No Encontrado", "No existe un contacto con ese nombre.", "OK");
                TelefonoContactoEntry.Text = "";
            }
        }
    }

    {

        if (!string.IsNullOrWhiteSpace(nombre))
        {
            string ruta = ObtenerRuta(nombre);
            if (File.Exists(ruta))
            {

Usa los datos que acabamos de insertar para responder a estas preguntas. Intenta resolverlas antes de ver la solución.

Consultas Básicas e Intermedias
  1. Pregunta: ¿Cuántos productos hay en total?
    Respuesta: SELECT COUNT(*) FROM Productos; → Resultado: 9
  2. Pregunta: ¿Cuál es el precio del producto más caro?
    Respuesta: SELECT MAX(Precio) FROM Productos; → Resultado: 1200.50
  3. Pregunta: Muestra todos los clientes que se registraron en 2023.
    Respuesta: SELECT * FROM Clientes WHERE YEAR(FechaRegistro) = 2023; → Devuelve 5 clientes.
  4. Pregunta: Lista todos los productos de la categoría 'Ropa'.
    Respuesta: SELECT * FROM Productos WHERE CategoriaID = 3; → Devuelve 2 productos.
  5. Pregunta: Muestra los pedidos que aún no han sido 'Entregado'.
    Respuesta: SELECT * FROM Pedidos WHERE Estado != 'Entregado'; → Devuelve 3 pedidos.
Consultas Avanzadas para Análisis y Dashboards
  1. Pregunta: ¿Cuál es el total de ventas (ingresos) de todos los tiempos?
    Respuesta: SELECT SUM(Cantidad * PrecioUnitario) AS IngresosTotales FROM DetallesPedido;
  2. Pregunta: ¿Qué cliente ha gastado más dinero en total?

    SELECT TOP 1 c.Nombre, SUM(dp.Cantidad * dp.PrecioUnitario) AS TotalGastado
FROM Clientes c
JOIN Pedidos p ON c.ClienteID = p.ClienteID

APIs RESTful: Comunicando Aplicaciones 🔌

En el desarrollo moderno, las aplicaciones rara vez contienen todos sus datos y lógica internamente. En su lugar, se comunican con servidores a través de la web para obtener información, autenticar usuarios, guardar datos y mucho más. La forma estandarizada y más popular de lograr esta comunicación es a través de una API RESTful.

¿Qué es una API (Application Programming Interface)?

1️⃣ Una API es un conjunto de reglas, definiciones y protocolos que permite que diferentes aplicaciones de software se comuniquen entre sí. Es un "contrato" que un servicio ofrece para que otros puedan interactuar con él sin necesidad de conocer su implementación interna.

2️⃣ Imagina que estás en un restaurante. Tú (la aplicación cliente) no vas a la cocina a prepararte la comida. En su lugar, hablas con el camarero (la API), le das tu pedido (una petición), y él se encarga de comunicarse con la cocina (el servidor) y traerte tu plato (la respuesta). La API es ese intermediario estandarizado.

¿Qué es REST (Representational State Transfer) y RESTful?

REST no es un protocolo ni un estándar, sino un estilo de arquitectura de software para sistemas distribuidos como la web. Una API que sigue los principios de REST se denomina **RESTful**.

  • Cliente-Servidor: Hay una clara separación entre el cliente (que consume los datos, como tu app MAUI) y el servidor (que los almacena y provee).
  • Sin Estado (Stateless): Cada petición del cliente al servidor debe contener toda la información necesaria para ser entendida. El servidor no guarda ningún "estado" o "sesión" del cliente entre peticiones.
  • Uso de la Interfaz Estándar de HTTP: REST aprovecha al máximo el protocolo HTTP, utilizando sus verbos y códigos de estado para realizar operaciones.
Protocolo HTTP y sus Verbos: El Lenguaje de la Web

HTTP (Hypertext Transfer Protocol) es el protocolo fundamental de la World Wide Web. Las APIs RESTful lo utilizan para realizar las operaciones CRUD. Cada operación se mapea a un "verbo" o "método" HTTP:

Verbo HTTP Operación CRUD Descripción y Uso
GET Read (Leer) Solicita y recupera datos de un recurso. Es una operación segura e idempotente (llamarla N veces produce el mismo resultado).
POST Create (Crear) Envía datos al servidor para crear un nuevo recurso. El cuerpo (body) de la petición contiene los datos (generalmente en JSON).
PUT Update (Actualizar) Reemplaza completamente un recurso existente con los nuevos datos proporcionados en el cuerpo de la petición.
DELETE Delete (Borrar) Elimina un recurso específico en el servidor.

Además, las APIs responden con códigos de estado HTTP para indicar el resultado de la petición: 2xx (Éxito, ej. 200 OK, 201 Created), 4xx (Error del cliente, ej. 400 Bad Request, 404 Not Found), 5xx (Error del servidor).

🛡️ Principio I: Protegerás los Secretos como si fueran Código Compilado

La primera regla de la seguridad en software es simple: el código es público, los secretos son privados. 🔐 Escribir cadenas de conexión, `API keys` o tokens directamente en tus archivos .cs o .xaml es una vulnerabilidad crítica. En un mundo donde el código vive en GitHub, cada línea expuesta puede costarte reputación, dinero o acceso. Proteger los secretos es proteger tu sistema, tu equipo y tu futuro.

✅ La Práctica Correcta en .NET: appsettings.json, Secret Manager y Azure Key Vault

Para desarrollo local, .NET utiliza el archivo appsettings.json y el Administrador de secretos (Secret Manager), que guarda los secretos fuera de la carpeta del proyecto. En producción, los secretos se gestionan con un servicio especializado como Azure Key Vault. Este servicio cifra, rota y audita tus secretos de forma centralizada y segura.

  • Usa appsettings.Development.json para configuraciones de desarrollo no sensibles.
  • Añade appsettings.Development.json y secrets.json a tu .gitignore. Este paso es crucial.
  • Usa el Administrador de secretos de .NET para tus claves de desarrollo. Haz clic derecho en el proyecto -> "Administrar secretos de usuario".
  • En producción (Azure), tu API debe leer los secretos desde Azure Key Vault, nunca desde un archivo de configuración en el repositorio.

Escenario Real: Un desarrollador sube su API de ASP.NET a GitHub. El archivo appsettings.json contiene la cadena de conexión a la base de datos de Azure SQL. En horas, bots escanean el repositorio, roban la cadena de conexión y secuestran los datos. ¿La solución? Utilizar el Administrador de secretos en desarrollo y leer la cadena de conexión desde Azure Key Vault en producción.

🐞 Principio II: Diagnosticarás Antes de Curar (Errores, Warnings, Analizadores)

Un ingeniero de software .NET no solo arregla bugs. Entiende la diferencia entre un error de compilación, una excepción en tiempo de ejecución y una advertencia de analizador. Diagnosticar antes de curar es el principio que separa al programador aficionado del profesional.

🛑 Errores (Compilación y Ejecución)

Los errores de compilación detienen la construcción de tu app (sintaxis incorrecta). Las excepciones en tiempo de ejecución (NullReferenceException, FormatException) detienen tu app mientras se usa. No son opcionales: deben ser corregidos o manejados con bloques try-catch.

⚠️ Warnings del Compilador

Son consejos del compilador de C#. Te avisan de peligros, como una variable no utilizada, un posible `null`, o el uso de métodos obsoletos (`[Obsolete]`). Ignorarlos es acumular deuda técnica. Visual Studio te los muestra claramente para que los corrijas.

🧹 Sugerencias de Analizadores (Roslyn)

El motor de C# (Roslyn) y herramientas como StyleCop analizan tu código en tiempo real. Te sugieren mejoras de estilo, rendimiento y buenas prácticas. Por ejemplo, te proponen usar `var` o convertir un `if` en una expresión ternaria. Son tu mentor de código personal.

🧪 Principio III: Confiarás en tu Código, Porque lo Has Probado

El testing es la red de seguridad de tu software. Es la diferencia entre la esperanza ("creo que la lógica del ViewModel funciona") y la certeza ("sé que funciona porque los tests lo comprueban"). Escribir tests te permite refactorizar y añadir funcionalidades a tu app .NET MAUI o a tu API de ASP.NET sin miedo. Frameworks como xUnit, NUnit o MSTest son el estándar en el ecosistema .NET.

💡 Ejemplo de Test Unitario con xUnit para un ViewModel


// Se necesita el paquete NuGet 'xUnit' y 'Moq'
public class CounterViewModelTests
{
    [Fact] // Atributo que marca esto como un test
    public void IncrementCommand_WhenExecuted_IncrementsCount()
    {
        // Arrange (Organizar)
        var viewModel = new CounterViewModel();
        var initialCount = viewModel.Count;

        // Act (Actuar)
        viewModel.IncrementCommand.Execute(null);

        // Assert (Afirmar)
        Assert.Equal(initialCount + 1, viewModel.Count);
    }
}
